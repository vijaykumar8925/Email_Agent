 1. EXECUTIVE SUMMARY
====================================================================================================

Mail Agent is an AI-powered email management platform designed for Gmail. Its primary objective is
to ingest incoming emails, categorize and triage them by importance and urgency, generate tailored
reply drafts using Large Language Models (LLMs), and strictly enforce a Human-in-the-Loop (HITL)
security model where no email can be sent without explicit cryptographic human approval.

CURRENT MATURITY LEVEL:
-----------------------
- Overall Project Maturity: MVP+ / Late Stage Prototype (72% Production Ready)
- Security Invariants & Cryptographic State Machine: Production Grade (95%)
- Local AI Integration & Fallback Engine: Production Grade (90%)
- UI/UX & Dual-Theme System: High Quality MVP (85%)
- Async Task Workers & Real-Time Sync: Incomplete Prototype (35%)
- Scalability & Concurrency: Early Stage (50%)
- Test Automation & Quality Assurance: Needs Work (45%)

KEY HIGHLIGHT:
The project features an exceptional foundation in domain-enforced safety. The cryptographic SHA-256
approval seal (ADR 0003), MultiFernet OAuth token vault, and state-machine-driven send pipeline
provide enterprise-grade safeguards against prompt injections and accidental auto-sends.

PRIMARY BLOCKER:
The background worker infrastructure (`workers/run.py`), Google Pub/Sub push notification webhooks,
and distributed task queues (`arq`) documented in `docker-compose.yml` and `architecture.md` are
currently stubbed or missing. Mailbox synchronization is currently invoked synchronously via HTTP,
which will time out on large mailboxes or slow local LLM hardware.

 3. ARCHITECTURE & CODEBASE INVENTORY
====================================================================================================

3.1 BACKEND ARCHITECTURE (FastAPI, SQLAlchemy 2.0 Async, Pydantic v2)
--------------------------------------------------------------------
- Router -> Service -> Repository Pattern:
  Properly implemented across `auth`, `emails`, `drafts`, `ai`, and `users`.
  Routers only parse requests and serialize schemas. Services maintain transaction boundaries
  (`async with session.begin()` or explicit commits) and state transitions. Repositories abstract
  SQL queries using SQLAlchemy 2.0 `select(...)` and `insert(...)` async statements.
- Structured Telemetry:
  `structlog` with JSON formatting in production and colored terminal output in development.
  `RequestIdMiddleware` generates or propagates `X-Request-ID` across every log entry.
- Error Handling:
  RFC 7807 compliant Problem Details responses implemented in `mailagent.core.errors.py`
  (e.g., `NotFoundError`, `AuthorizationError`, `InvalidStateTransitionError`, `ContentTamperError`).
- Health Probes:
  `/api/v1/healthz` (liveness) and `/api/v1/readyz` (deep dependency checks testing PostgreSQL
  query execution and Redis ping).

3.2 FRONTEND ARCHITECTURE (Next.js 16, React 19, Tailwind CSS v4)
-----------------------------------------------------------------
- App Router: Next.js 16 with single-page dashboard at `apps/web/src/app/page.tsx`.
- Theme System: Fully reactive Dark and Light mode theme provider with zero flicker (`ThemeProvider`),
  supporting system preference detection and localStorage persistence.
- Inbox View: Rich email client with category pills (Work, Finance, Personal, Alerts, Newsletters,
  Promotions, Other), importance indicators, search filters, and draft editor drawer.
- AI Playground: Live interactive testing interface for running prompt tests and evaluating local
  model latencies.
- Architectural Gap:
  The codebase has feature skeleton directories (`features/auth`, `features/drafts`,
  `features/settings`, `features/templates`) containing only re-exports or empty files. Almost
  all logic is consolidated into `InboxView.tsx` (834 lines) and `page.tsx` (727 lines). Refactoring
  these into modular subcomponents is recommended.

3.3 AI SUBSYSTEM (Ollama Local LLM + Anthropic Claude)
------------------------------------------------------
- Pluggable Provider Architecture:
  `BaseAIClient` abstracts LLM chat completion. `OllamaClient` targets local Ollama (`/api/chat`
  and `/api/tags`), while `AnthropicClient` targets Claude Messages API.
- Resilient JSON Parser:
  `extract_json_from_text` extracts valid JSON objects even when LLMs wrap output in markdown
  fences (```json ... ```) or conversational commentary.
- Two-Stage Processing:
  1. Classifier (`CLASSIFIER_SYSTEM_PROMPT`): Evaluates category, importance (1-5), urgency,
     summary, and recommended next step.
  2. Drafter (`DRAFTER_SYSTEM_PROMPT`): Composes contextual replies with tone control
     (professional, friendly, concise, assertive, urgent) respecting user instructions.

3.4 DATABASE & DATA STORAGE
---------------------------
- PostgreSQL 16 schema with UUID primary keys and UTC timestamps.
- Tables:
  * `users`: Google sub ID, email, profile details.
  * `oauth_credentials`: MultiFernet encrypted access/refresh tokens with expiration timestamps.
  * `mailboxes`: User mailbox bindings with `last_synced_at` and `history_id`.
  * `email_threads`: Gmail thread metadata and unread state.
  * `email_messages`: Parsed MIME messages, bodies, snippets, AI categories, importance, and summaries.
  * `drafts`: Reply drafts with status lifecycle, tone, approved content SHA-256 seal, and idempotency key.
  * `audit_logs`: Immutable security audit log tracking approvals, edits, tamper alerts, and sends.
- Migration Management:
  Alembic migrations configured in `apps/api/src/mailagent/db/migrations/versions/`.

3.5 SECURITY & CRYPTOGRAPHY
---------------------------
- ADR 0003 Implementation:
  Cryptographic SHA-256 seal guarantees that what the user approves is byte-for-byte identical to
  what Gmail dispatches. If an approved draft is modified, its status immediately drops back to
  `DRAFTED`. If a compromised request attempts to send modified text, the server rejects it with
  `ContentTamperError` and records a security incident.
- Token Storage:
  Google refresh tokens are never stored in plaintext. They are encrypted using `cryptography.fernet.MultiFernet`.
- Session Management:
  Signed cookies using `itsdangerous.URLSafeTimedSerializer` with `httpOnly`, `SameSite=Lax`, and `Secure`.

4.2 WHAT IS ALREADY PRODUCTION GRADE:
- Token encryption at rest and key rotation via MultiFernet.
- Explicit human approval domain barrier (AI cannot send emails autonomously).
- Concurrency control via row locks (`SELECT ... FOR UPDATE`) preventing double sends.
- RFC 7807 structured error responses and structlog request tracing.
- Alembic database migration management.
- Dual-theme system adhering to WCAG contrast guidelines.

4.3 CRITICAL GAPS & PRODUCTION BLOCKERS:
- BLOCKER 1: Broken Worker Container:
  `docker-compose.yml` launches `worker` with command `python -m mailagent.workers.run`.
  This file does not exist in the repository. Running `docker compose up` will crash the worker.
- BLOCKER 2: Synchronous Mailbox Sync:
  `/api/v1/mailboxes/sync` pulls messages and triages them within the HTTP request lifecycle.
  When syncing 20-50 messages on a local LLM taking 3-8 seconds per inference, the request will
  exceed reverse proxy timeouts (NGINX/Cloudflare 30s/60s).
- BLOCKER 3: Fire-and-Forget In-Process Background Tasks:
  The current triage offloads remaining messages to `asyncio.create_task()`. In a multi-worker
  production setup (e.g. Gunicorn/Uvicorn with multiple workers or Kubernetes pods), background
  tasks are terminated abruptly on container restarts and cannot be distributed across machines.
- BLOCKER 4: Rate Limiting Configured but Not Enforced:
  `config.py` defines `rate_limit_auth`, `rate_limit_ai`, `rate_limit_send`, but no rate limiting
  middleware or Redis limiter is attached to the routes.

 5. SECURITY & RESILIENCE VULNERABILITY ANALYSIS
====================================================================================================

1. CSRF DEFENSE IN DEPTH:
   - Status: Minor Risk
   - Detail: The application uses `SameSite=Lax` session cookies, which blocks cross-site POSTs
     in modern browsers. However, `validate_csrf()` is defined in `security.py` but never registered
     in FastAPI dependencies. For full OWASP compliance, state-changing endpoints should require
     an `Origin` check or an `X-CSRF-Token` header.

2. OLLAMA LOCAL ENGINE CONCURRENCY BOTTLENECK:
   - Status: High Operational Risk
   - Detail: By default, Ollama processes one prompt completion at a time per GPU/CPU thread.
     If a user triggers a mailbox sync while simultaneously testing in the AI Playground,
     requests will queue, resulting in high latency or HTTP client timeouts.
   - Fix: Configure `OLLAMA_NUM_PARALLEL=4` in Ollama environment and offload triage strictly
     to background workers with Redis task throttling.

3. GOOGLE OAUTH WATCH / WEBHOOK EXPIRATION:
   - Status: Architectural Gap
   - Detail: Google Cloud Gmail Push Notifications (`watch()`) automatically expire every 7 days.
     A production system requires a scheduled cron/worker job that calls `users.watch` every 5-6
     days to maintain the webhook subscription.

 7. NEXT-GEN AGENTIC CAPABILITIES TO MAXIMIZE EFFECTIVENESS
====================================================================================================

To elevate Mail Agent from a reactive email assistant into an indispensable, autonomous productivity
powerhouse, the following agentic systems should be introduced:

7.1 MULTI-AGENT COLLABORATIVE WORKFLOW
--------------------------------------
Instead of relying on a single monolithic LLM prompt, split email processing into specialized agents:

1. Ingestion & Triage Specialist (The Sorter):
   - Fast, lightweight model (e.g., Llama-3.2-3B or Mistral-7B).
   - Classifies email, detects spam/newsletters, assesses urgency, and flags priority items.

2. Context & Sentiment Investigator (The Analyst):
   - Analyzes full historical email threads to understand ongoing project context and relationships.
   - Extracts deadlines, agreed action items, and emotional sentiment (e.g. frustrated client).

3. Personal Style Drafter (The Voice):
   - Generates replies matching the user's specific writing style, sign-offs, and tone.

4. Fact-Checker & Safety Auditor (The Critic):
   - Reviews drafted responses against company guidelines, verifies dates, flags potential
     commitments, and verifies that no sensitive data (passwords, tokens, PII) is leaked.

7.2 RETRIEVAL-AUGMENTED GENERATION (RAG) & STYLE MEMORY
-------------------------------------------------------
- Sent Email Style Fine-Tuning / Memory:
  Index the user's past 200 sent emails in a local vector store (e.g., ChromaDB or pgvector).
  When drafting a reply to a client, retrieve similar past replies to reproduce the user's exact
  vocabulary, greetings, and closing signatures.
- Knowledge Base / Documentation Grounding:
  Allow the user to upload product manuals, pricing sheets, and project documentation.
  When an incoming email asks "What is our refund policy?" or "What is our deployment schedule?",
  the agent retrieves the accurate information rather than guessing.

7.3 TOOL-AUGMENTED ACTION AGENTS (CALENDAR & TASK TRACKING)
----------------------------------------------------------
- Google Calendar Meeting Agent:
  * Detects scheduling requests ("Are you free this Thursday at 2 PM?").
  * Uses Google Calendar API tool to inspect the user's free/busy slots.
  * Formulates a draft reply: "I am free Thursday at 3 PM or Friday at 10 AM. I have placed a
    tentative hold on your calendar."
- Action Item & Task Extraction:
  * Automatically detects commitments made in incoming messages (e.g., "Send revised deck by 5 PM").
  * Integrates with productivity tools (Todoist, Notion, Linear, Google Tasks) to create tasks.

7.4 PROACTIVE EXECUTIVE BRIEFINGS (AGENTIC MORNING DIGEST)
----------------------------------------------------------
- Every morning at 8:00 AM, the agent generates an executive briefing:
  * "You have 3 high-importance emails requiring decisions today."
  * "1 contract renewal requires signature."
  * "2 drafts are pre-generated and awaiting your one-click approval."
- Delivered via email summary, Telegram notification, or dashboard banner.

7.5 AUTONOMOUS TRIAGE RULES ENGINE
----------------------------------
- Allow users to configure rule policies:
  * "If sender is VIP (e.g. CEO or key client), send instant push alert."
  * "If category is 'newsletters' or 'promotions', auto-archive and skip inbox."
  * "If email contains an invoice PDF, download attachment and save to Receipts folder."

 8. SUMMARY RECOMMENDATIONS & CONCLUSION
====================================================================================================

Mail Agent possesses an exceptionally solid architectural foundation. Its core strengths include:
1. Strict adherence to human-in-the-loop security (cryptographic hash seals).
2. Clean separation of concerns across FastAPI routers, services, and repositories.
3. Flexible support for both local Ollama LLMs and cloud Anthropic Claude models.
4. An aesthetically refined, responsive Next.js frontend with dual-theme support.

Immediate priority should be given to:
1. Creating the background ARQ worker service (`workers/run.py`) to prevent HTTP request timeouts.
2. Connecting rate limiting and CSRF protection to all API endpoints.
3. Evolving from single-prompt generation to multi-agent drafting with calendar and style memory.

With these enhancements completed, Mail Agent will represent an enterprise-ready, privacy-first,
highly effective AI email executive assistant.
